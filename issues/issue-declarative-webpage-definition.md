# Replace webpage component registration with a declarative role-aware hierarchy

Example webpage: `gPronto.Framework:issues/webpage-example.ts`

## Webpage field reference

The table defines the complete future structure of `GProntoFrameworkRegisteredWebpageDefinition`.
The table columns are:

- `Field`: the property path in `GProntoFrameworkRegisteredWebpageDefinition`.
- `Cardinality`: the number of times the field occurs within its immediate parent.
- `Type`: the field's non-null TypeScript type; a field whose only permitted value is `null` has type `null`.
- `Null`: whether the field permits `null`; `Allow` permits it and `Not allow` prohibits it.
- `Possible values`: the allowed value or value category for the field.
- `Description`: additional information about the field that is not a constraint. All constraints belong in `Possible values`.

The cardinality values are:

- `1`: exactly one occurrence.
- `0..n`: zero or more occurrences.
- `1..n`: one or more occurrences.

The field-path placeholders are:

- `<role>`: `standard` or `admin`.
- `<role_application_value>`: one configured normalized `role_application` value.
- `<open_slot>`: one **Open slot** required by the selected **gLayout**.
- `<gComponent_Prop>`: one public prop of the selected **gComponent**.

In the `Possible values` column:

- a value enclosed in backticks and double quotation marks, such as `"path"`, is a string literal;
- a value enclosed only in backticks, such as `true`, `null`, or `{}`, is the literal value shown;
- a name enclosed in backticks within an object description, such as `role`, is an object property name.
